# 役割分担定義 (Roles)

## ツール別の担当領域

| 役割 | ツール | 動作環境 | AIエンジン | 典型的な作業 |
|------|--------|---------|-----------|-------------|
| 設計・仕様確定・レビュー | **Antigravity** | Antigravity IDE | 選択中モデルによる（Gemini 3.5 Flash / Gemini 3.1 Pro / Claude Sonnet 4.6 / Claude Opus 4.6 / GPT-OSS 120B 等） | 要件定義・仕様書作成・実装計画の策定・完成コードのレビュー・QAテスト |
| 実装（プログラミング） | **Claude Code** | ターミナル（VSCode等） | Claude | Antigravityが確定した仕様に基づくコーディング・複数ファイル横断変更・スクリプト作成・ビルド |
| インライン編集 | **Cursor** | Cursor IDE | Claude（Composer） | エディタ上での局所的な修正・補完・クイックフィックス・デバッグ |
| 計画・承認 | **Human** | — | — | 方針決定・最終レビュー・本番適用・優先度判断 |

## 作業フロー

```
Human が方針を決定
    ↓
Antigravity が設計・仕様書を作成
    ↓
Human が仕様を承認
    ↓
Claude Code が実装（HANDOFF.md で仕様を受け取る）
    ↓
Antigravity がコードレビュー・動作検証
    ↓
Human が本番適用を承認
```

## 判断基準

### Antigravityを使う場面
- 要件定義・仕様書（`implementation_plan.md`）の作成
- 実装完了後のコードレビュー・動作確認（QAテスト）
- ドキュメント作成・専門スキルの実行

### Claude Codeを使う場面
- Antigravityが確定した仕様を受けてのコーディング
- 複数ファイルをまたぐ実装・リファクタリング
- ターミナルでのビルド・スクリプト実行

### Cursorを使う場面
- 特定ファイル内での局所的な編集（補完・リネーム・クイックフィックス）
- エディタ上でのデバッグ・コード読解

### Humanが介入する場面
- 方針の変更・優先度の変更
- セキュリティ・プライバシーに関わる判断
- 本番環境への適用・push・PR作成

## 引き継ぎプロトコル

1. 作業終了前に `HANDOFF.md` を更新する
2. 「次にやること」を具体的に記述する（曖昧な表現を避ける）
3. ブロックしている理由がある場合は明記する
4. 完了タスクは `handoff-log/` にアーカイブする
