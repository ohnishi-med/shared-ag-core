# スキル: environment-manager — 環境定義・バージョン管理エージェント

## このスキルについて

Node.js や Electron など、ローカルの動作環境に極めて強く依存するプロジェクトにおいて、バージョンの差異による意図しない不具合を防ぎ、すべての開発者・実行環境での一貫性を担保するためのスキルです。

## 得意分野

- 📦 **Node.js**: バージョン固定、エンジンの制約定義、LTS運用
- ⚡ **Electron**: バージョンの厳密管理、プレリリース回避による安定化

## 【最重要ルール】

- 全てのNode/Electron関連の新規システムおよび改修おいて、この定義ルールを逸脱した「曖昧な環境定義」をしてはいけません。
- Node.jsのデフォルト推奨バージョンは原則として **v24.15.0 (LTS)** を基準とします（要件で別の指定がない限り）。

## レビュー・構築の観点と対応

### 1. Node.js 環境の定義
- プロジェクトのルートディレクトリに必ず `.node-version` （または `.nvmrc`）ファイルを作成し、使用するバージョン（例: `24.15.0`）を単独で記述すること。
- プロジェクトの初期化時、`package.json` 内に必ず `engines` フィールドを含め、互換性を明示すること。
  ```json
  "engines": {
    "node": ">=24.15.0"
  }
  ```

### 2. Electron と Node.js バージョンの同期・厳密管理
- **【重要】** Electronは特定のNode.jsを内包しています。ネイティブモジュールのコンパイルエラー（ABIの不一致や齟齬）を防ぐため、**Electronを導入する際は必ずそのElectronバージョンが内包しているNode.jsのバージョンを調べ、プロジェクトの `.node-version` および `engines` をそのバージョンと完全に一致させてください。**
- Electron、TypeScript、ビルドツール等の重要パッケージは、`package.json` においてキャレット記法 `^` やチルダ記法 `~` を**使わずにExact Version（厳密指定）**で運用すること。
  - 例: `"electron": "30.0.1"` （`"^30.0.1"` は不可）
- バージョン差異によるトラブルを防ぐため、追加の `npm` コマンドを実行する際は必ず `--save-exact` フラグを使用した運用を徹底してください。

## 使用方法

> このプロジェクトの動作環境定義を environment-manager のルールに従って整備して。
> （あるいは、自身の作業の一環として常にこのルールを参照して実装すること）
