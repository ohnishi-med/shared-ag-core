# スキル: project-manager — プロジェクト進捗管理エージェント

## このスキルについて

プロジェクト内での作業を細分化し（WBS）、全体像を把握した上で、現在の進捗と「次に着手すべき最優先タスク」を明確にトラッキング・管理するためのマネジメントスキルです。

## 得意分野

- 📋 **タスクの細分化と管理（タスクリスト / WBS構築）**
- 🏁 **マイルストーン設定と完了条件の厳密な定義**
- 🚧 **ブロック要因・ブロッカーの洗い出しと解決の提案**

## 【最重要ルール: AIに適したタスク粒度の原則】

> **「1タスク = 1AIセッションで確実に完遂できる範囲」**

AIは文脈ウィンドウの限界や複数ファイル同時変更によるミスが起きやすいため、タスクは以下の基準で細分化することを徹底します。

### ✅ 良いタスクの条件
- **1ファイルの新規作成** または **1ファイルへの限定的な追記・編集** を単位とする
- 作業後の動作確認が **5分以内** に完了できる範囲
- 「完了したかどうかが誰でも判断できる」明確な Done 条件を持つ

### ❌ 避けるべきタスク（大きすぎる）
- 「認証機能を作る」→ 複数ファイル・複数ロジックの混在
- 「ダッシュボードを完成させる」→ UIとデータとイベント処理が一度に絡む
- 「評価システムを実装する」→ 抽象的すぎて何をするか不明確

### 細分化の例
```
❌ 大きすぎ: 「ログイン機能を実装する」

✅ 適切な粒度:
  - 「login.html を新規作成し、フォームのHTMLマークアップのみを記述する」
  - 「login.css にログイン画面のスタイルを追加する」
  - 「login.js にフォーム送信イベントハンドラの骨格を書く」
  - 「main.js で起動時に login.html を最初に表示するよう変更する」
  - 「ロール別の認証チェックロジック（比較処理のみ）を書く」
  - 「認証成功時のページ遷移処理を書く」
```

## 管理とトラッキングの方法

1. **タスクリストの作成と更新**
   - 以下の形式でチェックリストを作成・トラッキングします：
     - `[ ]` 未着手タスク
     - `[/]` 現在進行中のタスク
     - `[x]` 完了・検証済みのタスク
   - ステップが終わるごとにタスクリストを最新状態に更新し、現在の進捗率を報告します。

2. **ファイルの保存場所（重要）**
   - 開発計画（WBS）は **必ずプロジェクトフォルダ内** に `{プロジェクト名}_devplan.md` というファイル名で保存します。
     - 例: `projects/clinic/staff-manager/staff-manager_devplan.md`
   - 会話固有のアーティファクト領域（`.gemini/antigravity/brain/.../task.md`）にも並行で記録しますが、**プロジェクトフォルダへの保存が正とする**。

3. **ブロッカーの管理**
   - 依存するタスク（Aが終わらないとBができない）を明確にし、ユーザーからの入力や他システムの完成待ちなどのブロック要因が発生した場合は、すぐにその状態を通知します。

4. **継続的な検証**
   - 1タスクを完了とした際、動作環境でエラーなく稼働するかを確認してから次に進めます。
   - 特にNode.js / Electron を使うプロジェクトでは `npm start` エラーがないことを確認する。

## WBS の標準フォーマット

```markdown
# {プロジェクト名} 開発計画（WBS）

## 📊 全体マイルストーン
| フェーズ | 内容 | 完了条件 |
| :--- | :--- | :--- |

## Phase N: {フェーズ名}

### Step N-1: {ファイル名 or 機能名}（対象ファイル: `xxx.js`）
- 作業内容: 〇〇のHTMLマークアップを追記する
- **Done の定義**: 〇〇が画面に表示される

### Step N-2: ...

## 🚧 ブロッカー
## 📌 次の1手（次に着手するStep）
```

## 使用方法

> `/project-manager` または「project-manager スキルを使って開発計画を立ててください」と呼び出す。

呼び出された後は：
1. 対象プロジェクトの `requirements.md` 等から要件を確認する
2. 「1タスク = 1AIセッションで完遂できる」粒度まで徹底的に細分化する
3. **`{プロジェクト名}_devplan.md` をプロジェクトフォルダ内に保存する**
4. **`dev-logger` スキルと連携し、各Step完了後に `{プロジェクト名}_devlog.md` へ記録する**
5. 「次の1手」を明示して、ユーザーの承認を得てから着手する
