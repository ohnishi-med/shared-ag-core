# 匿名化と実患者データの取り扱い

読むタイミング: 投稿前の匿名化チェック時、実患者データ(PHI)を扱う作業全般。

## 患者データの匿名化(投稿前に必須のチェック)

**絶対日付(実際の受診日等)をそのまま本文に残さない。** 投稿直前に以下のいずれかで匿名化する:
- 相対日付化: "Day 1", "Week 3" のように発症/初診からの経過日数表記に統一する
- 日付シフト: 全ての日付を一定期間(例: +180日)ずらす(イベント間の相対間隔は保持される)

あわせて以下も確認する:
- 施設名・氏名・住所等の識別情報が本文・表・図・画像(スクリーンショット等)に残っていないか
- **年齢は通常そのまま(正確な数字)記載してよい。** ただし HIPAA Safe Harbor 基準に準じ、**89歳以上の場合は "90歳以上" のようにまとめる**(高齢層は人口統計的に希少になり、地域・施設情報と組み合わせて特定されやすいため)
- 郵便番号レベルの詳細地名や、症例の希少性が極端に高く施設名と組み合わせると一意に特定できてしまう場合は、その旨を記載レベルの調整で緩和する
- 他院・前医の対応の当否を示唆しうる記述(退院経緯の詳細等)は、正確な事実関係が不明な場合は特にリスクが高い。事実として確認できない限り、理由の記載自体を削り「転院した」等の事実のみに留める
- Declarations の "Consent for publication" に、患者(または代理人)から publication 用の同意を取得した旨を明記する

## 実患者データを扱う場合の注意

- 実在患者のPHI(個人識別可能な医療情報)を含むシステムにアクセスする前に、ユーザー(医療者本人)に「その内容を外部AIサービス経由でこの会話に読み込ませてよいか」を明示的に確認する。同意なしにPHIを取得・解析しない。
- 実データから抽出した値は、CSV等の中間ファイルに単位・出典・判読不能箇所を明記して保存し、原稿に反映する際は必ず出典データと照合する。単位表記の食い違い(例: cmH₂O と mmHg の混同)は特に注意する。
- 査読(セルフレビュー)で事実誤認や内部矛盾を発見した場合、本文中の該当表現を grep で全て洗い出してから一括修正する(部分修正は新たな内部矛盾を生みやすい)。
- ユーザーから新しい臨床情報(検査値、既往、臨床グレード等)が追加で提供された場合、それが既存の記載(重症度分類の内訳等)に波及効果を持たないか都度検討する。1つの事実の追加・訂正が、独立して見える別の箇所(スコア計算、鑑別診断の根拠リスト等)の再計算を要することがある。
- **ある事象(症状・イベント)の原因や対応(投薬等)についてユーザーから訂正が入った場合、既存の関連する時系列データ(投与記録・CSV等)と自動的に照合する。** 訂正後の記述が「その日」なのか「次のセッション」なのか等、時間的な対応関係を憶測で決めず、既存データに実際にその対応を裏付ける記録があるか確認してから記述する。ユーザーの発言自体が推測(「〜じゃないかな」)である場合は、その旨を踏まえて過度に断定的な因果表現にしない。
